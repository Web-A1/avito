# План тестирования build-feed.js

Этот документ описывает пошаговый план тестирования объединяющего скрипта `build-feed.js`.

## Подготовка тестовых данных

### 1. Тестовый план (data/plan_test.json)

Создайте минимальный тестовый план с одной задачей:

```json
{
  "tasks": [
    {
      "material": "sand",
      "materialId": "karier_neseyan_nemyt_pesok",
      "slots": [
        {
          "DateBegin": "12.12.2025 10:00",
          "count": 3,
          "locations": [
            {
              "address": "Московская область, Троицк",
              "count": 3
            }
          ]
        }
      ]
    }
  ]
}
```

### 2. Тестовый Excel (data/current_test/)

Положите один `.xlsx` файл с минимум 2-3 объявлениями. Можно использовать существующий файл или создать упрощенный.

### 3. Тестовые правила обновления (update_old_ads_test.json)

```json
{
  "byId": {
    "4908236909": {
      "updatePhoto": true,
      "materialId": "karier_neseyan_nemyt_pesok",
      "updateDescription": "auto",
      "customTitle": "Песок карьерный тестовый"
    }
  },
  "byLists": {
    "updatePhoto": ["4908236909"]
  }
}
```

**Важно:** Используйте реальные `AvitoId` из вашего тестового Excel файла.

## Пошаговое тестирование

### Этап 1: Проверка чтения данных

**Цель:** Убедиться, что скрипт корректно читает все входные файлы.

```bash
# Тест 1.1: Чтение плана
npm run build:feed -- --plan data/plan_test.json --test-step 1

# Ожидаемый результат:
# ✅ План прочитан, найдено задач: 1
# ✅ Алиасы материалов/адресов (если есть)

# Тест 1.2: Чтение Excel
npm run build:feed -- --plan data/plan_test.json --current-dir data/current_test --test-step 2

# Ожидаемый результат:
# ✅ Excel прочитан, найдено объявлений: N
# ✅ Примеры Id показаны

# Тест 1.3: Чтение правил обновления
npm run build:feed -- --plan data/plan_test.json --current-dir data/current_test --update-rules update_old_ads_test.json --test-step 3

# Ожидаемый результат:
# ✅ Правила прочитаны, найдено правил: N
# ✅ Статистика по типам обновлений
```

### Этап 2: Проверка генерации фото для старых объявлений

**Цель:** Убедиться, что фото для старых объявлений генерируются корректно.

```bash
# Тест 2.1: Генерация фото (без загрузки на Диск)
npm run build:feed -- \
  --plan data/plan_test.json \
  --current-dir data/current_test \
  --update-rules update_old_ads_test.json \
  --test-step 4 \
  --skip-upload

# Ожидаемый результат:
# ✅ Фото сгенерированы в data/photos/<materialId>/temp_updates/
# ✅ Файлы имеют правильные имена (AvitoId.jpg)
# ✅ Фото содержат водяной знак

# Проверка вручную:
ls -la data/photos/karier_neseyan_nemyt_pesok/temp_updates/
# Должны быть файлы с именами AvitoId.jpg
```

### Этап 3: Проверка загрузки фото на Яндекс.Диск

**Цель:** Убедиться, что фото корректно загружаются и публикуются.

```bash

  --plan data/plan_test.json \
  --current-dir data/current_test \
  --update-rules update_old_ads_test.json \
  --test-step 4-6 \
  --skip-new-photos

# ✅ Фото загружены на Яндекс.Диск
# ✅ Получены публичные URL
# ✅ Локальные файлы удалены
# ✅ Маппинг сохранен в output/photos_links_<date>.json

# Проверка вручную:
cat output/photos_links_*.json | jq '.items[] | select(.avitoId)'
# Должны быть записи с avitoId и public_url
```

## Режим тестирования

Скрипт поддерживает следующие флаги для тестирования:

- `--test-step N` - выполнить только шаг N
- `--test-step N-M` - выполнить шаги с N по M
- `--skip-photos` - пропустить генерацию и загрузку фото
- `--skip-upload` - пропустить загрузку на Яндекс.Диск
- `--skip-new-photos` - пропустить генерацию фото для новых объявлений
- `--skip-old-photos` - пропустить обновление фото для старых объявлений
- `--skip-updates` - пропустить обновление описаний/заголовков
- `--skip-generation` - пропустить генерацию новых объявлений
- `--dry-run` - режим "сухого прогона" (показывает, что будет сделано, но не выполняет)
- `--test-output-dir` - использовать отдельную папку для тестовых файлов

## Типичные проблемы и решения

### Проблема: "План не найден или пуст"
**Решение:** Проверьте путь к плану и формат JSON

### Проблема: "Excel не найден"
**Решение:** Убедитесь, что файл находится в указанной папке и имеет расширение .xlsx

### Проблема: "YANDEX_DISK_TOKEN не найден"
**Решение:** Установите переменную окружения или используйте `--skip-upload`

### Проблема: "Не указан materialId"
**Решение:** Добавьте materialId в правила обновления для объявлений с updatePhoto: true

### Проблема: "Адрес не найден в списке утвержденных"
**Решение:** Используйте только адреса из CITY_ALIASES (см. src/constants/materialAliases.js)

## Следующие шаги

После успешного тестирования всех этапов:

1. Протестируйте на реальных данных (с меньшим количеством объявлений)
2. Проверьте производительность на большом объеме
3. Убедитесь, что все файлы корректно создаются и удаляются
4. Проверьте работу в production режиме
