# План тестирования флагманского фото

## Цель
Проверить, что при повторной генерации фото:
1. Флагманское фото остается в старых объявлениях и не меняется
2. Новые генерации выполняются по обычным правилам (с искажениями)
3. Все исходники используются, включая тот, который был для флагманского фото

## Шаг 1: Первая генерация (создание флагманского фото)

### Подготовка
1. Убедитесь, что в `data/photos/karier_neseyan_nemyt_pesok/бронницы,_магистральная_ул.,_3/` нет файла `flagship.jpg`
2. Убедитесь, что в истории (`hashes.json`) нет записей для `s00_bron_*_01`

### Выполнение
```bash
npm run photo:variants
```

### Ожидаемый результат
1. **В логах должно быть:**
   - `Флагманское объявление уже было: НЕТ`
   - `Генерируется флагманское фото (первое для товара+локация)`
   - `Начинаем с: 01 (флагманское)`
   - Для первого фото: `Тип: Флагманское фото (без искажений)`
   - Для остальных фото: `Тип: Генерация с трансформациями`

2. **Созданные файлы:**
   - `data/photos/karier_neseyan_nemyt_pesok/бронницы,_магистральная_ул.,_3/flagship.jpg` (должен быть создан)
   - `data/photos/karier_neseyan_nemyt_pesok/бронницы,_магистральная_ул.,_3/variants/s00_bron_161225_01.jpg` (флагманское, без искажений)
   - `data/photos/karier_neseyan_nemyt_pesok/бронницы,_магистральная_ул.,_3/variants/s00_bron_161225_02.jpg` (с искажениями)
   - И т.д.

3. **Проверка флагманского фото:**
   - Откройте `s00_bron_161225_01.jpg` - должно быть без геометрических искажений (только водяной знак)
   - Сравните с `s00_bron_161225_02.jpg` - должно быть видно различие (искажения во втором)

4. **Проверка истории:**
   - В `hashes.json` должна быть запись с `adId: "s00_bron_161225_01"` и `counter: 1`

## Шаг 2: Вторая генерация (повторная, флагманское уже есть)

### Подготовка
1. Сохраните хеш флагманского фото из первой генерации:
   ```bash
   # Можно проверить в hashes.json или посмотреть на файл
   ls -lh data/photos/karier_neseyan_nemyt_pesok/бронницы,_магистральная_ул.,_3/variants/s00_bron_161225_01.jpg
   ```

2. Увеличьте `count` в `plan.json` для той же локации (например, с 5 до 10)

### Выполнение
```bash
npm run photo:variants
```

### Ожидаемый результат
1. **В логах должно быть:**
   - `Флагманское объявление уже было: ДА`
   - `Найдено в истории: s00_bron_161225_01` (или другая дата, если изменили)
   - `Флагманское фото уже было для этого товара+локация`
   - Для ВСЕХ фото: `Тип: Генерация с трансформациями` (включая первое!)

2. **Проверка флагманского фото:**
   - Файл `s00_bron_161225_01.jpg` НЕ должен быть пересоздан (проверить время модификации)
   - Хеш файла должен остаться прежним

3. **Новые файлы:**
   - Должны быть созданы новые фото с counter > 1 (например, `s00_bron_171225_02.jpg`, `s00_bron_171225_03.jpg` и т.д.)
   - ВСЕ новые фото должны иметь искажения (включая первое в новой генерации)

4. **Проверка использования исходников:**
   - В логах должно быть видно, что используются разные исходники
   - Исходник, который был использован для флагманского фото, должен использоваться и для новых фото (но с искажениями)

## Шаг 3: Проверка использования всех исходников

### Подготовка
1. Убедитесь, что в `data/photos/karier_neseyan_nemyt_pesok/originals/` есть несколько исходников (минимум 3-5)

### Выполнение
```bash
npm run photo:variants
```

### Ожидаемый результат
1. **В логах должно быть видно:**
   - Для каждого исходника: `Исходник: <имя_файла>`
   - Все исходники должны быть использованы для генерации фото

2. **Проверка распределения:**
   - Если есть 5 исходников и нужно создать 10 фото, каждый исходник должен использоваться примерно 2 раза
   - Исходник, который был для флагманского фото, должен использоваться и для обычных фото (но с искажениями)

## Шаг 4: Визуальная проверка

### Проверка флагманского фото
1. Откройте `s00_bron_161225_01.jpg` (флагманское)
2. Должно быть:
   - Без геометрических искажений (не повернуто, не масштабировано)
   - Без цветовых искажений (естественные цвета)
   - Только водяной знак

### Проверка обычных фото
1. Откройте несколько обычных фото (например, `s00_bron_161225_02.jpg`, `s00_bron_161225_03.jpg`)
2. Должны быть видны:
   - Геометрические искажения (поворот, масштаб)
   - Цветовые искажения (яркость, насыщенность)
   - Водяной знак
   - Паттерны уникализации (если видны)

## Шаг 5: Проверка истории

### Проверка hashes.json
1. Откройте `data/photos/karier_neseyan_nemyt_pesok/бронницы,_магистральная_ул.,_3/hashes.json`
2. Должна быть только ОДНА запись с `counter: 1` для этого товара+локация
3. Все остальные записи должны иметь `counter > 1`

## Команды для быстрой проверки

```bash
# Проверить, есть ли флагманское фото
ls -lh data/photos/karier_neseyan_nemyt_pesok/бронницы,_магистральная_ул.,_3/flagship.jpg

# Проверить все созданные фото
ls -lh data/photos/karier_neseyan_nemyt_pesok/бронницы,_магистральная_ул.,_3/variants/

# Проверить историю
cat data/photos/karier_neseyan_nemyt_pesok/бронницы,_магистральная_ул.,_3/hashes.json | grep -A 5 "counter.*1"

# Проверить хеш флагманского фото (после первой генерации)
md5 data/photos/karier_neseyan_nemyt_pesok/бронницы,_магистральная_ул.,_3/variants/s00_bron_161225_01.jpg

# Проверить хеш после второй генерации (должен совпадать!)
md5 data/photos/karier_neseyan_nemyt_pesok/бронницы,_магистральная_ул.,_3/variants/s00_bron_161225_01.jpg
```

## Ожидаемые проблемы и их решения

### Проблема: Флагманское фото пересоздается при повторной генерации
**Решение:** Проверить логику `hasFlagshipAd` - она должна проверять историю независимо от даты

### Проблема: Первое фото в новой генерации тоже флагманское
**Решение:** Проверить условие `if (i === 0 && counterOffset === 0 && !hasFlagshipAd)` - должно быть `!hasFlagshipAd`

### Проблема: Исходник для флагманского фото не используется для обычных фото
**Решение:** Проверить логику выбора исходников - все исходники должны использоваться равномерно
